## 1. 一句话结论

两者是**同一条技术路线**：CDP 操控 DeepSeek 网页 → 让模型输出“工具调用” → 本地执行 → 把结果回喂。

- **EAgent 的功能面更宽**：扩展工具（PowerShell / 截图 / 上传 / 鼠标 / 键盘）、26 个技能包、浏览器窗口置入、随机延迟防风控。
- **EAgentX 的工程化更强**：网页版 + API 双引擎、限流自动恢复、命令完整性校验、发送间隔、步数/超时、轨迹审计、可配置选择器、16 项自检。
- **提示词是两种哲学**：EAgent 追求“纯工具块、无限轮、不要拒绝”；稳定版 EAgentX 追求“少轮次、可恢复、保留安全边界”；
  UI 版则直接采用 EAgent 原文提示词，只由宿主保留审批、步数和 `[TASK_DONE]` 收尾。

## 2. 技术架构

| 维度 | 开源 EAgent | EAgentX |
| --- | --- | --- |
| 宿主 | 易语言 WinForms，单 exe（README 称 < 3 MB） | C# WinForms，单 exe（201,216 字节） |
| 权限 | README 要求右键**以管理员身份运行**（部分系统操作需要） | 默认**普通权限**；需要提权的命令由用户自行处理 |
| 浏览器 | 启动 Edge/Chrome，独立临时 profile | 启动 Edge/Chrome，独立 profile（`%APPDATA%\EAgentX\edge-profile`） |
| 浏览器窗口 | 可 `--app` 无地址栏；可 SetParent **嵌进主窗口**（实验性） | 普通标签页，独立窗口，方便登录/看页面 |
| CDP 连接 | 每次操作启动一个 PowerShell 脚本，脚本内临时连 WebSocket | 常驻 C# `ClientWebSocket`，注入 JS Helper（与原 exe 逐字节一致） |
| 页面操作 | 脚本内 JS + 固定选择器 | 注入 JS（选择器可配置）+ `Input.dispatchKeyEvent` |
| 发送编码 | 文本转 Base64 传给脚本，避免引号问题 | JSON-RPC 直接传字符串 |
| 配置 | 基本写死（工作目录、UI 选项） | `%APPDATA%\EAgentX\config.json`，原子写入 |
| 更新 | 启动时 HTTP 检查 `auto_update.txt`，提示下载 | 无自动更新，手动替换 exe |
| 可审计性 | 易语言工程 + 模块，核心逻辑在 `code.e` | 全部 C# 源码，可逐行阅读、可复现编译 |

**取舍**：EAgent 的“每步起一个 PowerShell 脚本”实现简单、崩溃隔离好，但每步多两次进程启动 + WebSocket 握手；EAgentX 常驻连接更快，但页面刷新后要重新注入。

## 4. 工具对比

### 4.1 PowerShell（两者都有，细节差别很大）

| 项目 | EAgent | EAgentX |
| --- | --- | --- |
| 执行方式 | 写 `.ps1` → `cmd` 调 PowerShell → 输出重定向到 `*_out.txt` | 写 `.ps1` + 宿主 runner → `powershell -NoProfile -NonInteractive -File` |
| 进程隔离 | 每步新进程，且执行前 `taskkill /F /IM powershell.exe /T`、`pwsh.exe` | 每步新进程（`-File`），**不**杀用户其它 PowerShell |
| 输出上限 | 4,000 字符 | 12,000 字符（超长保留头 8,000 + 尾 3,000） |
| 命令上限 | 4,000 字符 | 6,000 字符 |
| 编码 | 输出文件 Unicode → Ansi | 强制 UTF-8，失败回退 GBK/Default，去 BOM |
| 超时 | 无命令级超时 | 默认 120 秒，Kill + `taskkill /T` |
| 交互命令 | 禁止 `Read-Host`/`pause`/`more`/`cmd /k` | 同样禁止，另禁 `notepad` 等 |
| 工作目录 | 用户选的目录（脚本里 `cd`） | `WorkingDirectory` + 提示词约束 |

> EAgent 的“杀所有 PowerShell”是为了避免上一步的脚本残留；代价是会误伤用户自己开的 PowerShell/构建任务。EAgentX 选择只杀自己那棵进程树。

### 4.2 截图 / 上传 / 鼠标 / 键盘（EAgent 独有）

- **截图**：全屏或按窗口句柄；截图前把自己的窗口调到最透明，并弹出 20×20 的黄色鼠标位置标记。硬件加速窗口（浏览器/UWP）用 `PrintWindow` 可能截出黑图，这是 Windows API 的通病。
- **上传**：模型输出 `agent_getfile_head('D:\1.jpg', ...)`，程序把文件塞进网页附件框；单文件 100 MB、最多 50 个。
- **鼠标**：逻辑坐标，支持左键单击/双击、右键单击/双击；要求先移动+截图确认 DPI，再点击。
- **键盘**：虚拟键码 1–3 个 + 可选窗口句柄；谨慎使用 Alt+F4/Esc，可能把 Agent 自己关掉。

EAgentX 没有这 4 个工具。它的“上传文件”是**用户主动**选文件，不是模型按路径取文件；图片/PDF 走网页附件，文本走 PowerShell 读取。

### 4.3 技能包

EAgent 把 `skill_all.zip` 写到临时目录，提示词要求“先检查 skill，能用就用”。压缩包共 108 个文件、26 个技能，例如：

`bad-apple-cli`、`nx-auto-modeling`、`ai-claim-checker`、`cue-omni-reader`、`daily-standup-journal`、`decision-matrix`、`diagram-maker`、`documentation-writer`、`exam-ready`、`frontend-design`、`ledger-tasks-yylo`、`linkedin-post-formatter`、`meeting-note-summarizer`、`orca-replay`、`plugin-scanner`、`retrieval-practice-generator`、`sandbase`、`skillhub-cli`、`storytelling-advisor`、`study-strategy-selector`、`time-blocking-scheduler`、`triage-nda`、`video-frames`、`weather`、`zero-slop`、`zhangxuefeng-skill`。

EAgentX 没有技能包机制，靠提示词 + 临时命令完成同类任务。

## 5. 提示词对比（摘要，详见 [`提示词对比.md`](提示词对比.md)）

| 维度 | EAgent | EAgentX |
| --- | --- | --- |
| 协议 | 纯代码块 + 特殊注释标记（`powershell_tool_调用工具_识别头`） | 一个 ```powershell 块 + `[TASK_DONE]` |
| 单轮工具数 | 1 个，且只能 1 次 | 1 个块，但块内可多条语句/多个 cmdlet |
| 轮次策略 | 每一步只做一件小事，拆多轮 | 一个任务尽量 3–8 条命令做完 |
| 长度 | 命令/输出各 4,000 字符 | 命令 6,000 / 输出 12,000 |
| 全新进程 | 明确说明，且杀所有 PowerShell | 明确说明，保留用户进程 |
| 显式成败 | `Write-Output "OK"` / `"DONE: n"` | 同样要求 |
| 破坏性操作 | 先只读确认，禁止通配符批量删除 | 同样，并要求先说明风险 |
| 反问 | 信息不足时主动提问 | 不反问；确实缺信息用 `[NEED_INPUT]` |
| 拒绝话术 | **明令禁止**“我不能/无法/替代方案” | 保留拒绝能力 |
| 语气 | 允许脏话/网络用语 | 不采用 |
| 只回文字 | 不会发生（协议要求每轮必须有工具） | 自动催 2 次；`[NEED_INPUT]` 不催 |
| 失败策略 | 同一操作失败 2 次必须换方案 | 未写死，靠模型自行判断 |

**为什么 EAgentX 的提示词只有一半长**：EAgent 的 8,459 字符里有 4 个额外工具的完整语法、技能包检查、规划模板和语气规则；EAgentX 只有 PowerShell，所以把篇幅集中在“少轮次、命令完整、输出可控”上。

## 6. 2026-10-19 的 5 个更新，逐条对照

| 更新 | EAgent 做法 | EAgentX 现状 | 建议 |
| --- | --- | --- | --- |
| 1. 截图工具 | 把自己的窗口从“隐藏”改为“调到最透明”，减少截图残影；继续显示鼠标位置标记 | 没有截图工具 | 不适用；将来若加，需同样处理自身遮挡 |
| 2. 防风控 | 固定延迟 → **随机延迟**；浏览器加 `--disable-blink-features=AutomationControlled`、`--test-type` | 固定间隔（从回答结束起算）；Edge 启动参数没有这两个 | 可考虑（见 §9），不是缺陷 |

## 7. 可靠性与安全性

### 7.1 可靠性

| 场景 | EAgent | EAgentX |
| --- | --- | --- |
| 网页限流 | 不处理，只能等或重启 | 识别“消息发送过于频繁”，指数退避重发 |
| 页面改版 | 选择器写死在脚本里，需改源码 | 设置里改 5 个选择器 |
| 长回复被截断 | 4,000 字符硬限制，靠模型拆轮 | 6,000/12,000，且检测未闭合围栏/残片 |
| 命令卡死 | 无超时 | 120 秒超时杀进程树 |
| 模型只回文字 | 协议上不允许，实际可能卡住 | 自动催 2 次 |
| 进程残留 | 每次发送前杀所有 PowerShell | 只杀自己启动的进程树 |
| 配置损坏 | 基本无配置 | 临时文件 + `File.Replace` |
| 日志膨胀 | 无 | 4 MB 轮转 |
| 会话留痕 | PS 历史文件 | Markdown 轨迹（用户/助手/命令/结果/审批） |

### 7.2 安全性

两者**都没有沙箱、没有命令白名单、没有参数级审查**。模型生成的 PowerShell 会以当前用户权限真实执行。

- EAgent 的 README 要求以管理员身份运行，一旦模型生成恶意命令，影响范围更大；README 也明确写“无安全系统”。
- EAgent 的提示词**禁止模型拒绝**，并要求“把用户目标视为预授权”，这会进一步降低模型对危险操作的抵抗力。
- EAgentX 默认普通权限、默认逐条审批、提示词保留拒绝能力，并要求破坏性操作先只读确认；但“自动批准”打开后同样等于全权执行。
- 两者都通过 CDP 自动化操作网页版，**都违反 DeepSeek 用户协议**；EAgent 的 README 也明确说明了封号风险。EAgentX 的限流重试能减少“失败后手忙脚乱重复发”，但不能消除账号级限制。

## 8. 各自优势与短板

### EAgent 更强的地方

1. **工具面宽**：截图、上传、鼠标、键盘，能处理纯 GUI 任务（安装器、老软件、游戏/设计工具）。
2. **模型可主动取文件**：不用用户先点“上传”，模型自己按路径把图片/PDF 拉进对话。
3. **技能包**：26 个现成技能，开箱即用。
4. **浏览器整合**：`--app` + 窗口置入，看起来像一个完整的桌面应用。
5. **自动更新**：启动即检查新版本。
6. **防风控更新更快**：随机延迟、隐藏自动化标识。

### EAgentX 更强的地方

1. **双引擎**：网页版之外还能接 OpenAI 兼容 API，网页版故障时可切换。
2. **限流恢复**：不会因为一次“发送过于频繁”整条任务链断掉。
3. **协议更稳**：通用 ```powershell 围栏 + 十余种语言别名 + 无标记单块兼容，不依赖特殊注释标记。
4. **命令校验**：引号/括号/here-string/结尾操作符检查，残片不执行。
5. **可控性**：步数、回复超时、命令超时、发送间隔、选择器都可调。
6. **可审计**：完整 C# 源码、Markdown 轨迹、日志轮转、16 项自检。
7. **不打扰用户环境**：不杀其它 PowerShell、不关用户的浏览器、普通权限运行。
8. **提示词更聚焦**：少轮次、批量命令，直接针对“回答太少、反复追问”的真实故障。

### 共同短板

- 都依赖 DeepSeek 网页 DOM，页面大改就可能失效。
- 都没有真正的沙箱/回滚/权限隔离。
- 都只能“看文本/附件”，没有原生多模态视觉（EAgent 靠截图绕开）。
- 都不支持多任务并行。

## 9. 如果继续向 EAgent 靠拢，优先级建议

| 优先级 | 项目 | 理由 | 风险/成本 |
| --- | --- | --- | --- |
| P1 | Edge 启动加 `--disable-blink-features=AutomationControlled` 等 | 与上游最新防风控一致，改动一行 | 可能影响调试；不保证不被识别 |
| P1 | 发送间隔可选“固定/随机区间” | 上游用随机延迟降低规律性 | 需要改设置 UI 与测试 |
| P2 | 截图工具（全屏/窗口 + 鼠标标记） | GUI 任务必需；可复用现有 CDP/命令通道 | 需要图片回传通道（网页附件/API 多模态） |
| P2 | 模型按路径取文件（上传工具） | 比用户手选更自然 | 需要解析路径 + 安全提示 |
| P3 | 鼠标/键盘工具 | 覆盖安装器/老软件 | 风险最高，容易误操作 |
| P3 | 技能包 | 26 个技能直接可用 | 体积/维护/来源审查 |
| P3 | 自动更新检查 | 与上游一致 | 需要稳定的发布地址与签名 |
| 不建议 | 浏览器窗口置入 | 实验性，DPI/登录/调试都更麻烦 | 维护成本高 |
| 不建议 | “禁止拒绝/允许脏话”提示词 | 降低安全边界，与功能无关 | 无收益 |

---

## 10. 结论

- 想要**功能覆盖**（截图、鼠标键盘、技能、模型主动取文件）→ EAgent 更合适。
- 想要**稳定跑长任务、可配置、可审计、可切换 API** → EAgentX 更合适。
- 两者不是替代关系，而是同一路线的两种取舍：EAgent 更像“全能小工具”，EAgentX 更像“可维护的工程实现”。
- 本轮 EAgentX 的修复集中在真实故障（限流、空转、命令残片、发送间隔、提示词约束），没有为了“对齐上游”而引入高风险工具或削弱安全边界。
