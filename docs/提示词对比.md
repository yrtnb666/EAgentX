# 提示词对比：EAgentX vs 开源 EAgent

对比对象：开源项目 [YaoGaoChaoLe/EAgent](https://github.com/YaoGaoChaoLe/EAgent)（易语言版）源码里的
`#常量_初始化提示词`（`code.e`，`System Prompt` 开头的那一段）。EAgentX 的提示词在
`src/Core/PromptBuilder.cs` 的 `BuiltIn()` 里，用户填了自定义提示词时整体被替换。

> 版本说明：上游最新 release 为 **2026-10-19**。这次“5 个优化”提交（`251ce39`）里
> `code.e` 是 `+0/-0`，**提示词没有变化**，下面的逐条对比仍然适用。
> 架构、工具、安全、更新等全量对比见 [`与EAgent对比.md`](与EAgent对比.md)。
>
> **UI 版注意（2026-10-20）**：下面的逐条差异描述的是**稳定版 EAgentX**。`EAgentX-新UI版`
> 已改为直接嵌入 EAgent 原文提示词（`assets/eagent_prompt.txt`），并支持原版 扩展工具标记；
> UI 版的差异以 [`UI版说明.md`](UI版说明.md) 为准。

## 逐条对比

| 维度 | 开源 EAgent | EAgentX（本次调整后） | 结论 |
| --- | --- | --- | --- |
| 核心形式 | 用「模拟工具调用」的代码块驱动 PowerShell | 同样是一个 ```powershell 代码块 + 结果回喂 | 一致 |
| 单轮数量 | 一轮只有一个代码块、只能调一个工具 | 每条回复只给一个代码块，但**块内可以写多条语句/多个 cmdlet** | 采用，并写得更明确 |
| 代码块外的文字 | 要求纯代码块，块外不允许任何字符 | 允许不超过 3 行的说明（首轮计划也在这里） | 不采用“纯块”，否则界面太干、用户看不懂在干什么 |
| 命令长度上限 | 4000 字符，超了就拆多轮 | 6000 字符，超过才拆 2–4 段 | 放宽（宿主已修复长回复完成判定） |
| 结果回传上限 | 4000 字符，建议用“上传文件”读大文件 | 12000 字符，超出保留头 8000 + 尾 3000，并在提示里说明 | 放宽并显式告知模型 |
| 执行环境 | 每次全新 PowerShell 进程；执行前还会强杀所有 powershell/cmd 进程 | 每次全新进程（`-NoProfile -NonInteractive -File`），**不**强杀用户其它 PowerShell | 采用“新进程”，不采用“强杀”（会误伤用户正在跑的任务） |
| 状态保持 | 明确说明变量/函数/别名/当前目录都不保留 | 同样明确说明，并要求“后一步要用的东西落到磁盘或写进同一条命令” | 采用（原 EAgentX 缺这条，是拆成很多小步的原因之一） |
| 交互式命令 | 禁止 `Read-Host`、`pause`、`more`、`cmd /k`、`Get-Credential` | 禁止 `notepad`、`pause`、`Read-Host`、`more`、`cmd /k` | 采用 |
| 大文件读取 | `Get-Content -TotalCount N`、`Select-Object -First N`，不要对整盘 `-Recurse` | 同样，并给出“单条命令输出 ≤ 100 行”的可执行标准 | 采用 |
| 判断成败 | 脚本末尾显式 `Write-Output "OK"` / `"DONE: $count"` | 同样写进规则 | 采用 |
| 编码 | 写文件指定 `-Encoding UTF8`；无 BOM 用 `[IO.File]::WriteAllText` | 同样写进规则 | 采用 |
| 破坏性操作 | 先只读确认再执行，禁止通配符批量删除 | 同样，并要求先用一句话说明风险 | 采用 |
| 修改现有代码 | 最小改动、不顺手格式化、改完自检 | 同样（新增「修改现有文件」小节） | 采用 |
| 反问/空话 | 不废话、字数少；每轮必须给工具 | 不要反问、不要等确认、不说“好的/马上”；**只回文字时宿主自动催 2 次** | 采用并加强（这是“回答太少、要反复追问”的主因） |
| 确实需要用户信息 | 无专门约定（模型多半直接猜） | 允许用一句话提问并以 `[NEED_INPUT]` 结尾，宿主识别后不再催 | EAgentX 新增 |
| 拒绝话术 | 明令禁止输出“我不能/我无法/替代方案”等 | **不采用** | 安全边界应该保留，模型该拒绝时要能拒绝 |
| 语气 | 允许脏话、网络用语、情感化表达 | **不采用** | 与功能无关 |
| 工具种类 | PowerShell + 截图 + 上传文件 + 鼠标 + 键盘 | 只有 PowerShell（附件上传由界面“上传文件”单独完成） | 设计差异，不在这轮范围内 |
| 步数限制 | 累计调用次数无限 | 默认 30 步（可调到 200） | 设计差异；批量化后 30 步通常够用 |

## 这次具体改了什么

1. **一条命令干一件事 → 一条命令干一批事**
   原提示词只说“每条回复最多一条命令”，模型会理解成“一次只能调用一个 cmdlet”，
   于是 `New-Item`、`Set-Content`、`Get-Content` 各占一轮。现在明确：一个代码块里可以写多条语句，
   “宁可一条命令做十件事，也不要分十条消息做十件事”。
2. **补上“全新进程、不保留状态”**
   这是原提示词缺失、而开源版有的关键约束。模型以前会写 `$x = ...` 然后下一条命令直接用 `$x`，
   必然失败，又要多花一轮排查。
3. **补上输出/读取限制和显式成败输出**
   让模型自己把输出压小、在末尾打印 `OK` / `DONE: n`，减少“看不出成功没有 → 再查一遍”的往返。
4. **只回文字时自动催**
   开源版的协议是“每轮必须给代码块”，所以不会出现空转；EAgentX 允许纯文字回复，
   原实现遇到纯文字就直接结束本轮，用户只能手打“继续”。现在宿主自动催 2 次，
   并区分“真的在等用户补充信息”（`[NEED_INPUT]`，不催）。
5. **发送间隔改为从回答结束起算**
   原实现从“上次发送开始”计时，模型回答十几秒就把间隔吃光了，设置形同虚设。
   现在从“回答到达”计时到“下次发送”，命令执行时间也计入。
6. **本机信息不再跟着自定义提示词“冻住”**
   提示词里的「操作系统 / 当前时间 / 工作目录 / 用户身份」四行由 `PromptBuilder` 在每次拼提示词时
   按当前机器重算（自定义提示词也走同一套刷新），所以换一台电脑不会残留上一台的用户名（比如 T8pro）和路径。

## 刻意保留的差异

- **不复制“禁止拒绝/允许脏话”**：那不是缺陷修复，且会削弱模型对危险操作的安全提示。
- **不复制“执行前强杀所有 powershell/cmd”**：会杀掉用户自己正在跑的脚本，风险大于收益。
- **不引入截图/鼠标/键盘工具**：超出本轮“修问题”的范围，且需要额外的权限与安全设计。
