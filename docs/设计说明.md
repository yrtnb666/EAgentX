# EAgentX 设计说明

## 1. 目标与约束

**目标**：在 Windows 上复刻开源项目 EAgent 的核心体验——让 DeepSeek 网页版“操控电脑”：

1. 选一个工作目录；
2. 自动拉起浏览器并复用用户已有的网页登录态；
3. 用户在桌面客户端里发任务，模型输出 PowerShell；
4. 客户端执行命令，把真实结果回喂；
5. 循环直到任务完成。

**约束**：

- **不使用易语言**（原版实现语言），改用 C# / .NET Framework 4.x；
- 产出**单个 exe**，不依赖 Python/Node/.NET SDK，不联网装包；
- 不反代、不逆向接口，只做页面自动化；
- 默认不自动执行模型命令，必须有人工审批。

## 2. 技术选型

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| Python + PyInstaller | 放弃 | 需要联网装 PyInstaller，产物 10+ MB，启动慢 |
| Tauri / Electron | 放弃 | 需要 Node + Rust 工具链，构建链路过重 |
| **C# WinForms + 系统自带 csc** | **采用** | Windows 自带编译器，0 依赖，产物约 180 KB，启动即用 |
| 易语言 | 放弃 | 用户明确要求 |

UI 使用 WinForms 手写布局（无 designer 依赖），深色主题；HTTP 用 `HttpClient`，
JSON 用 `JavaScriptSerializer`，WebSocket 用 `ClientWebSocket`——全部在 .NET Framework 内。

| `MainForm` | 会话生命周期、日志渲染、输入、审批回调、状态栏 |
| `SettingsForm` | 引擎 / 路径 / 超时 / 发送间隔 / 自动批准 / 选择器编辑（副本编辑，取消不落盘） |

## 5. 关键流程

### 5.1 连接（网页版）

```
StartAsync
  └─ EdgeLauncher.EnsureStarted
       ├─ GET /json/version 可通? → 复用
       └─ 否 → 启动 msedge --remote-debugging-port --user-data-dir ...
  └─ WaitForChatTargetAsync
       ├─ 轮询 /json/list，优先 deepseek.com 的 page
       └─ 连不到就 PUT /json/new?<startUrl> 建一个
  └─ CdpClient.ConnectAsync(webSocketDebuggerUrl)
  └─ Runtime.enable / Page.enable
  └─ 若当前 URL 不是 deepseek.com → Page.navigate + 等 readyState=complete
  └─ Runtime.evaluate(注入 Helper) → window.__eagentx
  └─ 读取 diag（输入框/按钮/回复节点/登录判断）
```

### 5.2 发送与取回复

```
setInput(text)                 ← 原生 setter + input 事件，React 才认
beforeSend()                   ← 记录消息节点 / 回复节点数
Input.dispatchKeyEvent(Enter)  ← 真实按键
WaitForSubmitted(8s)           ← 消息节点增加 / 开始生成 / 最后几条消息出现刚发文本
   └─ 都没发生 → 邻近度评分找发送按钮 → click → 再验证一次
轮询（默认 800ms）:
   replyState()                 ← 一次返回：回复文本、动作栏按钮数、生成状态
   动作栏出现（复制/重新生成） 且 停止方块消失 且 文本稳定 1.6s → 返回
   动作栏没抓到但看到过生成中 → 文本稳定 6.4s 才返回（兜底）
   检测到「消息发送过于频繁」→ 抛 RateLimitException，由 SendAsync 外层等待重发
超时 → 附上 diag（节点数、是否生成中、相关类名）
```

### 5.3 智能体循环

```
outbound = 首轮 ? System + Task : 上轮反馈
loop step ≤ MaxSteps:
    if 距上次回答结束不足 SendIntervalSec: Task.Delay 补足   ← 间隔从“回答到达”起算
    reply = engine.Send(outbound)
    记录/展示 reply
    cmd = CommandParser.Parse(reply)
    if 命令不完整（引号/括号/here-string 未闭合）: 不执行，要求模型重写
    if 没有命令:
        if [TASK_DONE]: 结束
        if [NEED_INPUT]: 结束（等用户补充）
        否则自动催「继续」，最多 2 次
    if 用户拒绝: outbound = 拒绝说明; continue
    result = PowerShellRunner.Run(cmd)
    展示退出码/输出；记录轨迹
    if 命令同时带 [TASK_DONE]: 结束
    outbound = Feedback(result)
```

## 6. 三个容易踩的坑（实现要点）

### 6.1 React 输入框不能直接赋值

`el.value = text` 不会触发 React 的 `onChange`。必须：

```js
Object.getOwnPropertyDescriptor(HTMLTextAreaElement.prototype, 'value').set.call(el, text);
el.dispatchEvent(new Event('input', { bubbles: true }));
```

### 6.2 发送按钮没有文字

DeepSeek 的发送键是 `div.ds-button--primary`，无 `aria-label`、无文本。
因此发送主路径改为 CDP 真实按键：

```
Input.dispatchKeyEvent { type: keyDown, key: Enter, code: Enter, windowsVirtualKeyCode: 13, text: "\r" }
```

发送后不能只看 `inputEmpty()`：DeepSeek 可能先清空输入框、后提交失败。
现在会等待 `.ds-message` 数量增加、主按钮进入生成状态，或最后几条消息出现刚发文本；
三者都没有才退回按邻近度评分点击按钮，并再验证一次。

### 6.3 innerText 会丢掉 Markdown 围栏

页面把代码块渲染成 `<pre><code>`，`innerText` 里**没有** ` ```powershell `，
导致解析器拿不到命令。解决办法：取回复时克隆节点，把每个 `<pre>` 反向序列化：

```
\n```<语言>\n<代码>\n```\n
```

语言优先取 `code.className` 里的 `language-xxx`，否则取代码块头部第一段 ASCII 文本
（DeepSeek 头部会拼上“复制/下载”，所以只取第一个 token，并在 C# 侧再做一次归一化）。

### 6.4 生成状态不能只看 aria-label，也不能先看 disabled

DeepSeek 生成期间，右侧主按钮 `div.ds-button--primary` 的图标会从发送箭头
`M8.3125...` 换成停止方块；生成结束后重新带 `ds-button--disabled` 并恢复发送箭头。
现场观测发现：**生成中也可能短暂出现 `disabled` 类**（服务端慢、按钮过渡），
如果先判断 `disabled` 就会把“正在生成”误判成“已完成”。所以 `E.generating()` 的顺序是：

1. SVG 里有停止方块 `M2 4.88...` → 生成中；
2. SVG 里有发送箭头 `M8.3125...` → 空闲；
3. 图标还没换过来时，非 `disabled` 一律按生成中处理（宁可多等）。

仅凭“停止按钮 + 文本稳定 1.6 秒”仍不够：长回复中途可能停顿超过 1.6 秒。
v1.0.4 增加了**消息底部动作栏**（复制/重新生成等按钮）作为完成信号，
并把它与停止按钮、文本稳定性三者一起判断。

### 6.5 长命令与少分段

模型曾按“每段 300–500 字符”把 HTML 拆成几十次 `Add-Content`，每次都要一轮发送/回喂，
既慢又容易触发网页限流。实际根因是旧版完成判定把停顿误判为结束，并非单条命令长度限制；
v1.0.3 在系统提示词里明确：

- 单条 PowerShell 命令 **6000 字符以内**可以一次写完；
- 写文件优先用 here-string / `Set-Content` 一次写完整内容；
- 只有确实超过 6000 字符才分段，每段尽量 2000–6000 字符，并标注“第 n/m 段”；
- 回喂提示也再次提醒“不要拆成很多次很小的 `Add-Content`”。

v1.0.4 又补了两层保险：

- 完成判定改为“动作栏出现 + 停止方块消失 + 文本稳定”，不再因中途停顿提前返回；
- `CommandShape` 检查命令是否完整，残片不执行，改为让模型重写；
- 如果当前对话已经被多次截断“带偏”，点「连接 / 新对话」开干净对话。实测新对话里
  模型可以一次输出 5519 字符的 `Set-Content` 命令。

注意：设置里的自定义提示词非空时会整体覆盖内置提示词。设置窗口现在会**预填内置提示词**：
没改动就存空串（继续跟随内置版本升级），改动后整段覆盖，并可点「恢复内置提示词」还原。
其中「操作系统 / 当前时间 / 工作目录 / 用户身份」四行是**本机信息**，`PromptBuilder.System()`
每次拼提示词时都会按当前机器重算（自定义提示词也一样），换电脑不会残留上一台的用户名/路径。
提示词与开源 EAgent 的逐条对比见 [`提示词对比.md`](提示词对比.md)。

v1.0.4 之后的提示词又补了几条直接影响往返次数的规则：

- 一个代码块里可以写多条语句，**能合并的操作必须合并**，不要把“改一个变量/替换一个字符串”拆成一整轮；
- 每条命令都在**全新 PowerShell 进程**里执行，变量/函数/当前目录不保留；
- 输出控制在 100 行以内、超过 12000 字符会被截断；读大文件用 `-TotalCount` / `-First`；
- 需要判断成败时在命令末尾显式输出 `OK` / `DONE: n`。

### 6.6 发送间隔与附件

- `Settings.SendIntervalSec` 默认 3 秒。`AgentSession` 记录上一次**回答到达**的时间，
  下一次发送前若不足 N 秒就 `Task.Delay` 补足。命令执行耗时也计入这段间隔（执行久就无需额外等待），
  这样设定的秒数才是“回答结束 → 下一条指令”之间真实存在的停顿。
- 命中网页版限流时，`WebEngine.SendAsync` 按 `RateLimitWaitSec` 等待后重发（每次翻倍，
  最多 `RateLimitRetries` 次），而不是直接中断整条任务链。
- 网页附件通过 CDP 的 `DOM.getDocument` → `DOM.querySelector('input[type=file]')`
  → `DOM.setFileInputFiles` 写入文件，DeepSeek 会正常显示附件卡片。
- API 模式或网页上传失败时，文件复制到 `<工作目录>\.eagentx\uploads\时间戳\`，
  并把本地路径写进输入框，模型可用 PowerShell 读取。

### 6.7 截断命令的隔离与解码

- **命令与宿主收尾代码分文件**：`PowerShellRunner` 把用户命令写到 `eagentx-cmd-*.ps1`，
  宿主再写一个 `eagentx-run-*.ps1`，后者 `&` 调用前者并处理退出码。这样即使命令
  以半截括号结尾，也不会把宿主的 `if (...)` 吞进同一个语法单元。
- **命令完整性检查**：`CommandShape` 扫描引号、here-string、`()`、`[]`、`{}` 和注释，
  拒绝未闭合或结尾停在 `-`、`|`、`=`、`+`、`&`、`` ` `` 的命令。命中后不执行，
  通过 `PromptBuilder.Incomplete()` 要求模型重新输出完整命令，连续 3 次失败才报错。
- **stderr 编码兜底**：不再假设 PowerShell 错误输出一定是 UTF-8。执行器直接读原始字节，
  先严格按 UTF-8 解码，失败再按系统 ANSI（中文系统 GBK）解码。语法错误发生在
  `[Console]::OutputEncoding = UTF8` 之前，这样也不会出现 `����` 乱码。

## 7. 稳定性设计

| 风险 | 处理 |
| --- | --- |
| 页面结构小改 | 选择器可配置；多级 fallback；按钮按位置评分 |
| 标签页不在目标站 | 连接后检查 URL，必要时 `Page.navigate` |
| 浏览器启动慢 | 25s 等调试端口、90s 等页面；超时给出明确提示 |
| 消息没发出去 | 验证消息节点/生成状态/刚发文本，失败再点按钮；超时日志带 diag |
| 网页限流 | `E.rateLimit()` 只检查最后一条消息，避免旧提示误报；命中后按设置等待并自动重发，超过重试次数才报错 |
| 长回复被截断 | 动作栏出现 + 停止方块消失 + 文本稳定 1.6s 才返回；没抓到动作栏则等 6.4s |
| 模型给出残片命令 | `CommandShape` 拒绝执行，回喂“命令不完整”，要求重写 |
| 命令语法错误乱码 | stdout/stderr 按字节读取，UTF-8 优先、ANSI/GBK 兜底 |
| 命令卡死 | 命令超时后 `Kill` + `taskkill /T /F`，并标记 `TimedOut` |
| 输出过大 | 保留头 8000 + 尾 3000 字符 |
| 模型死循环 | `MaxSteps` 上限；每步写入轨迹 |
| 多开互踢 | 单实例 Mutex |
| 配置损坏 | 反序列化失败回落默认值并 `Normalize()` |
| 线程跨界 | 所有 UI 更新走 `InvokeRequired/BeginInvoke` |

## 8. 安全设计

1. **默认人工审批**：`ApproveForm` 显示完整命令，`Enter` 允许、`Esc` 拒绝。
2. **自动批准可选**：设置里显式打开，开启时主界面打红色提示。
3. **超时与终止**：命令超时杀进程树；「停止」按钮取消整个任务。
4. **不内置密钥**：API Key 只存本机 `config.json`。
5. **可审计**：每条用户消息、模型回复、命令、退出码、输出都写入会话轨迹。
6. **明确边界**：不提供提权、不隐藏窗口执行、不修改系统策略。

> PowerShell 本身没有沙箱，命令仍可访问用户有权限的一切资源；审批是最后一道防线。

## 9. 已知限制

- 依赖 DeepSeek 前端结构：改版后可能需要更新选择器（已提供自检与可视化诊断）。
- 网页版有速率/账号风控，高频使用可能被限制。
- 回复完成判定依赖 DeepSeek 当前 DOM（动作栏 + 停止方块 + 文本稳定）；页面大改后可能需要调整。
  极端情况下仍可能提前或延后返回，因此再加了一层 `CommandShape` 残片拦截。
- 网页限流是账号级的，程序只能等待重发、不能绕过；建议把发送间隔设为 10 秒。
- 不支持流式逐字显示（网页 DOM 本身在流式刷新，但客户端拿到的是完整文本）。
- 未做代码签名，可能被杀软启发式误报。
- API 模式未实现 function calling，仍使用文本命令协议（好处：两种引擎行为一致）。
